#可视化鼠标键盘自动化工具

## 一、项目简介

该项目是一个单文件实现的 Windows 桌面自动化工具，由 **自动化执行引擎（`AutoClicker`）** 与 **Tkinter 图形界面（`AutoClickerGUI`）** 两部分构成，并以 `main()` 作为入口。

它把日常重复性的鼠标点击、键盘输入、等待、图像识别、文字识别（OCR）等操作抽象成「动作序列」，用户可以在界面上添加、排序、编辑、保存这些动作，然后一键按设定次数循环执行；也可以把序列导出为独立的 Python 脚本或 EXE 程序脱离本工具运行。

##二、典型用途

- 重复性表单填写、批量数据录入（含按序递增的数字填充）
- 固定流程的软件/网页操作自动化（点击、快捷键、输入、滚动、拖拽）
- 基于屏幕图像模板定位的点击（按钮位置会变化时按图找位置）
- 基于 OCR 的文字定位点击（按屏幕上的文字内容点击，不依赖图片模板）
- 需要「等待某个条件满足后再继续」的流程（等待时间、图片出现、窗口出现、剪贴板内容、按键）
- 需要条件分支/子循环的复杂流程编排


## 三、运行环境与依赖

### 3.1 运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows（代码使用 `ctypes.windll`、`APPDATA` 环境变量、管理员提权等 Windows 专属能力） |
| Python | Python 3.x（使用 f-string、`tkinter`） |
| GUI | Tkinter（Python 标准库自带，需随 Python 一同安装） |

### 3.2 依赖库

| 库 | 必要性 | 用途 |
|---|---|---|
| `pyautogui` | **必需** | 鼠标移动/点击/拖拽/滚动、键盘按键与输入、图像定位、FAILSAFE |
| `Pillow`（PIL） | 图像识别与托盘所需 | `pyautogui` 截图/图像匹配、托盘图标 |
| `pynput` | 依赖检查中按核心依赖处理 | 全局热键与键鼠监听；导入失败时 `PYNPUT_AVAILABLE = False`，相关功能降级 |
| `pystray` | 可选 | 系统托盘；导入失败时 `PYSTRAY_AVAILABLE = False` |
| `pyperclip` | 可选 | 剪贴板相关能力 |
| `rapidocr` / `rapidocr_onnxruntime` | 可选（OCR） | 首选 OCR 引擎，本地离线识别 |
| `pytesseract` | 可选（OCR 兜底） | 需另装 Tesseract-OCR 引擎 |
| `PyInstaller` | 可选 | 仅在导出 EXE 时需要，缺失可自动安装 |

### 3.3 安装方式

```bash
pip install pyautogui pynput pillow
# 可选：托盘
pip install pystray
# 可选：OCR（二选一）
pip install rapidocr
pip install rapidocr_onnxruntime
```

启动时会调用 `check_dependencies()`：若缺少 `pyautogui` 或 `pynput`，弹窗询问是否立即安装，确认后执行 `python -m pip install <缺失库> -i https://pypi.tuna.tsinghua.edu.cn/simple`。

## 四、使用方法与操作流程

### 4.1 启动


建议**以管理员身份运行**：否则全局热键可能无效，且无法操作部分需要提权的窗口。设置页「权限状态」区块会显示是否已获得管理员权限，未获得时可点击「点击获取管理员权限」（会先保存窗口位置，再用 `pythonw.exe` 以 `runas` 重启自身）。

### 4.2 基本操作流程

1. **添加动作**：在「动作序列」页点击底部动作按钮（或右键菜单「插入动作」），按对话框填写参数后确定，动作追加到列表末尾（右键插入则插到指定位置）。
2. **调整顺序与状态**：拖拽行调整顺序；右键启用/禁用、删除、批量操作；`Ctrl+Z` / `Ctrl+Y` 撤销重做。
3. **设置执行参数**：填写重复次数（留空/`-1` 为无限循环）、动作间隔（秒）。
4. **保存序列**：点击保存，可存为 `.json`（完整参数，推荐）或 `.txt`（可直接文本编辑）；下次通过加载或「最近脚本」菜单打开。
5. **执行**：点击「开始」或按 `F1`；执行过程中可暂停/继续（按钮或 `F3`）、停止（按钮或再次 `F1`）；日志面板与状态栏显示进度。
6. **导出分发**：需要脱离本工具运行时，用「导出 Python」或「导出 EXE」生成独立程序。

### 4.3 常用动作配置要点

- **移动鼠标**：填写目标 `x`/`y`（可用鼠标当前位置取值按钮）与移动时长 `duration`，时长越大移动越平滑。
- **相对移动**：基于当前坐标偏移 `dx`/`dy`，适合位置不固定但相对关系固定的场景。
- **图像识别点击**：先框选屏幕区域截图保存为模板图片，填写图片路径与置信度（越低越容易匹配但可能误匹配），可设置点击偏移与失败策略（跳过 / 重试 3 次 / 报错）。
- **文字定位点击**：填写要识别的文字，先精确匹配、再包含匹配；「第几个匹配」填 `-1` 表示取最后一个；可框选识别范围并设置置信度阈值。
- **填充数字**：设置总位数、起始值、结束值、前缀、后缀与输入间隔；每填完一个数字会记录进度到 `%APPDATA%\AutoClicker\fill_progress.json`，中断后可续填。
- **循环控制**：设置次数（`-1` 无限）、子动作间隔，并在对话框中录入子动作；子动作作为 `sub_actions` 嵌套执行。
- **条件控制**：选择检测类型并配置触发参数，再录入条件满足后要执行的子动作。

### 4.4 快捷键

| 快捷键 | 作用 |
|---|---|
| `F1` | 开始 / 停止执行（可在设置页改键） |
| `F2` | 记录当前鼠标位置（可在设置页改键） |
| `F3` | 暂停 / 继续执行（可在设置页改键） |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |
| `ESC` | 关闭最顶层弹窗 |
| 导出 EXE 中 `F1` / `F2` | 暂停继续 / 停止退出 |

## 五、配置项说明

### 5.1 程序自身配置文件

| 文件 | 位置 | 内容 |
|---|---|---|
| `.window_pos` | 与脚本同目录 | 主窗口几何信息（`geometry()` 原始字符串），启动时读取恢复位置 |
| `.recent_scripts` | 与脚本同目录 | JSON 数组，最近打开的脚本路径（上限 10 条） |
| `fill_progress.json` | `%APPDATA%\AutoClicker\` | 「填充数字」动作的续填进度 |

上述文件由程序自动读写，一般无需手工编辑。

### 5.2 设置页可配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| 故障安全（FAILSAFE） | 开启 | 开启后鼠标快速移到屏幕左上角 `(0,0)` 会触发 pyautogui 的紧急停止 |
| 执行进度可视化 | 开启 | 是否高亮当前执行的动作行 |
| 全局热键 | `f1` / `f2` / `f3` | 开始停止 / 记录位置 / 暂停继续，点击「选择按键」修改后需点「应用热键设置」 |
| 窗口置顶恢复 | 自动 | 恢复窗口位置时短暂置顶 3 秒并聚焦，随后取消置顶 |
| 撤销历史上限 | 50 步 | 代码内固定 `_max_history = 50` |

### 5.3 动作参数字典（供手写 JSON/TXT 参考）

```json
[
  {"type": "click", "kwargs": {"button": "left", "clicks": 1}, "enabled": true},
  {"type": "type", "kwargs": {"text": "hello", "interval": 0.1}, "enabled": true},
  {"type": "wait", "kwargs": {"wait_type": "time", "seconds": 1.5, "timeout": 30}, "enabled": true},
  {"type": "loop", "kwargs": {"repeat": 3, "interval": 0.5, "sub_actions": []}, "enabled": true}
]
```

TXT 格式示例（每行一个动作）：

```
# 格式: 类型 参数=值
click button='left' clicks=1
move x=100 y=200 duration=0.2
wait wait_type='time' seconds=1.0 timeout=30
```

> 注意：`save_as_txt` 头部注释列出的可序列化类型为 `move, move_rel, locate_click, click, double_click, right_click, left_click, scroll, press, type, hotkey, drag, wait, hold, key_hold, multi_key, multi_mouse, multi_key_mouse, open_file, open_url`；`loop`、`conditional`、`ocr_read`、`ocr_click`、`fill` 带嵌套结构或复杂参数，建议使用 JSON 保存。

## 六、注意事项

1. **管理员权限**：全局热键依赖键盘钩子，非管理员运行时可能失效；部分目标程序（以管理员运行的窗口）也需提权后才能被模拟操作。
2. **故障安全**：默认开启 FAILSAFE，鼠标急速移至屏幕左上角会抛出 `FailSafeException` 并中止自动化。执行前请确认该开关符合预期，避免流程被误中断。
3. **安全软件拦截**：键盘/鼠标钩子与模拟输入可能被安全软件判定为异常行为并拦截，需要时请添加信任。
4. **全屏游戏**：独占全屏模式下模拟输入与图像识别通常无效，请改为窗口化或无边框窗口模式。
5. **图像识别准确性**：模板图应来自与运行时相同的分辨率/缩放/主题；系统缩放变化会导致匹配失败。置信度过低会误点，过高会找不到。
6. **OCR 依赖与语言**：`pytesseract` 后端需要系统安装 Tesseract 并配置 `chi_sim`、`eng` 语言包；代码中硬编码了 `E:\Tesseract-OCR\` 路径，安装在其他位置时需保证 PATH 或语言包可用。RapidOCR 为纯本地推理，首次加载模型较慢。
7. **坐标与 DPI**：程序启动时设置了 DPI 感知；若在多显示器/不同缩放比例环境中坐标异常，建议统一缩放比例后重新截图模板。
8. **无限循环风险**：`repeat = -1` 会持续执行直至手动停止，请务必确认停止方式（按钮、`F1` 热键或故障安全）可用。
9. **文本格式的局限**：TXT 保存/加载不支持嵌套子动作与复杂结构，且字符串转义规则简单（含空格/引号/等号的值用 `repr` 包裹）；长期维护建议使用 JSON。
10. **导出 EXE**：需已安装 PyInstaller；导出时排除了 `numpy` 等模块以减小体积，若自动化流程间接依赖被排除的库，需自行调整排除列表。首次打包耗时较长，且部分杀毒软件会对新生成的单文件 EXE 报毒。
11. **配置文件位置**：`.window_pos`、`.recent_scripts` 写在脚本所在目录，若将脚本放入只读目录（如 Program Files），这两个文件将写入失败（会被异常捕获并打印，不影响主流程）。
12. **禁用动作**：被禁用的动作在序列中保留但不执行，日志会标注「跳过（已禁用）」；批量禁用后请确认流程逻辑仍然完整。
